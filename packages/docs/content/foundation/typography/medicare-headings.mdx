## Heading font family

Medicare.gov uses Inter for all headings.

The design system doesn't style base HTML typography elements (like `h1`, `h2`, `p`, etc.) unless they're inside an element with the [ds-content class](/foundation/typography/content). Instead, it provides heading classes (available on this page) corresponding to visual sizes. These classes can be applied to any heading elements, irrespective of their semantic heading level (`h1` to `h6`). This approach allows teams to first choose the semantic heading level that make the most sense for the document and its accessibility and then choose a visual heading size class that fits the page's visual hierarchy.

## Responsive typography

`.ds-text-heading--5xl`, `.ds-text-heading--4xl`, `.ds-text-heading--3xl`, `.ds-text-heading--2xl`, and `.ds-text-heading--xl` classes are responsive by default.

To apply responsive typography elsewhere, use the [font size utility class](/utilities/font/font-size/#responsive-font-sizes).
Since the base typography margins and line height is measured in `em` units,
they'll automatically adjust as you change the font size.

## Code

<Alert variation="warn" heading="First and last children">

The `.ds-text-heading--3xl` through `.ds-text-heading--sm` styles have alternate margins for headings that are the first or last child of their parent element. Headings that are the first child have no top margin, and headings that are last children have no bottom margin. The `.ds-text-heading--5xl` and `.ds-text-heading--4xl` styles carry no margins at all, so this does not apply to them. Some examples of what we mean:

```html
<main>
  <h1>I'm the first child of my parent.</h1>
  <h2>I'm not the first child of my parent</h2>
  <div>
    <h2>
      I'm actually the first child of my parent even though I'm not the first heading on the page
    </h2>
    <h2>I'm the last child of my parent</h2>
  </div>
  <h2>I'm also the last child of my parent</h2>
</main>
```

</Alert>

### Style customization

While styles are customizable, please refrain from making styling changes.

The following CSS variables can be overridden to change the type sizes.
Headings `xl` and larger use a smaller `--mobile` size below the `768px`
breakpoint:

| Heading | Default (below 768px)     | `md` breakpoint (768px and wider) |
| ------- | ------------------------- | --------------------------------- |
| `5xl`   | `--font-size-5xl--mobile` | `--font-size-5xl`                 |
| `4xl`   | `--font-size-4xl--mobile` | `--font-size-4xl`                 |
| `3xl`   | `--font-size-3xl--mobile` | `--font-size-3xl`                 |
| `2xl`   | `--font-size-2xl--mobile` | `--font-size-2xl`                 |
| `xl`    | `--font-size-xl--mobile`  | `--font-size-xl`                  |
| `lg`    | `--font-size-lg`          | `--font-size-lg`                  |
| `md`    | `--font-size-base`        | `--font-size-base`                |

The `lg` and `md` headings use a single size at every viewport width.

Line height is applied through the following variables, which do not change across breakpoints:

- `--font-line-height-heading-lg`, applied to `3xl` through `5xl` headings
- `--font-line-height-heading`, applied to `md` through `2xl` headings

Medicare headings also apply letter spacing through the following variables:

- `--font-letter-spacing-lg`, applied to `xl` through `5xl` headings
- `--font-letter-spacing-md`, applied to `lg` and `md` headings

## Guidance

### The `ds-content` class

For pages that are mainly about written content or places where you want to use a standard mapping of heading-level styles to semantic heading levels, consider using the [`ds-content`](/foundation/typography/content/) class.

### Layout dos and don'ts

There should always be a parent/child relationship between headers and content on the page. Every header should have a relationship to something else on the page. This can apply to many different relationships like a header and a form group or a header and list of links. Stray headers or content should be reevaluated.

- Paragraph styles should never be used as a parent to another text element.
- Header elements should never have equal or smaller font size than the paragraph element.
- Not all paragraphs need a header, but all headers need children.
- Every page should have one heading 1 (H1)
- Headings style appearing under H1 should follow a logical order for information design and supporting various assistive technology devices/software.
- Don't use a smaller header font size than the body font size
- Don't use stray headers
